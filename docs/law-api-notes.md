# 법제처 API 응답 모양 기록

- 확인일: 2026-11-20 (PLAN.md 1번 작업)
- 확인 방법: `npm run check:law` ([scripts/check-law-api.mjs](../scripts/check-law-api.mjs))
- 인증: `.env`의 `LAW_API_KEY`를 주소의 `OC` 항목으로 보낸다. 값은 이 문서에 적지 않는다.

## 결과 요약

| 자료 | 목록 조회 | 본문 조회 | 비고 |
|---|---|---|---|
| 법령 | 됨 | 됨 (JSON) | 조문과 부칙이 한 번에 내려온다. |
| 법원 판결 (출처: 대법원, 지방세법령정보시스템) | 됨 | 됨 (JSON) | |
| 법원 판결 (출처: 국세법령정보시스템) | 됨 | **JSON으로 안 됨** | 아래 "남은 문제" 참고 |
| 조세심판원 결정례 | 됨 | 됨 (JSON) | |

## 공통 호출 방법

- 목록 조회: `https://www.law.go.kr/DRF/lawSearch.do` + `OC`, `target`, `type=JSON`, `query`(검색어), `display`(건수)
- 본문 조회: `https://www.law.go.kr/DRF/lawService.do` + `OC`, `target`, `type=JSON`, `ID` 또는 `MST`(일련번호)
- 응답 안의 `...상세링크` 항목에는 인증값(`OC=...`)이 그대로 들어 있다. **이 항목은 화면이나 로그에 내보내지 않는다.**

## 1. 법령 (`target=law`)

**목록의 항목**: `법령명한글`, `법령일련번호`, `법령ID`, `현행연혁코드`(현행/연혁), `법령구분명`(법률 등), `시행일자`, `공포일자`, `공포번호`, `제개정구분명`, `소관부처명`, `법령상세링크`

**본문 조회**: `MST=법령일련번호`로 조회한다.

**본문의 항목**

- `기본정보` — 법령 이름, 공포번호 등
- `조문` → `조문단위` 목록 — 조문마다 `조문번호`, `조문시행일자`, 내용이 들어 있다. (국세기본법 기준 약 15만 자)
- `부칙` → `부칙단위` 목록 — 부칙마다 `부칙공포일자`, `부칙내용`이 들어 있다. (약 5만 자)
- `개정문`, `제개정이유`, `법령키`

법령 한 건이 매우 크므로, AI에게는 전체가 아니라 필요한 조문만 골라서 보내야 한다.

## 2. 법원 판결 (`target=prec`)

**목록의 항목**: `사건번호`, `사건명`, `선고일자`, `판례일련번호`, `데이터출처명`, `사건종류명`, `법원명`, `판결유형`, `판례상세링크`

`데이터출처명`은 `대법원`, `국세법령정보시스템`, `지방세법령정보시스템` 세 가지가 확인됐다. 출처가 국세법령정보시스템인 경우 사건번호가 `대법원-2026-두-30683`처럼 줄표가 들어간 형태이고, `법원명`과 `판결유형`이 비어 있다.

**본문 조회**: `ID=판례일련번호`로 조회한다.

**본문의 항목** (출처가 대법원, 지방세법령정보시스템인 경우)

- `사건번호`, `사건명`, `선고일자`, `법원명`, `사건종류명`
- `판시사항`, `판결요지`, `참조조문`, `참조판례`
- `판례내용` — 판결문 전문. 줄바꿈이 `<br/>`로 들어 있다.
- `판결유형` — 대법원 출처는 "판결", 지방세 출처는 "처분청 패소"처럼 결과가 들어 있다.

## 3. 조세심판원 결정례 (`target=ttSpecialDecc`)

**목록의 항목**: `청구번호`(예: 국심1993서0189), `사건명`, `의결일자`, `특별행정심판재결례일련번호`, `재결청`, `재결구분명`, `행정심판재결례상세링크`

**본문 조회**: `ID=특별행정심판재결례일련번호`로 조회한다.

**본문의 항목**

- `사건명`, `의결일자`, `세목`, `재결청`
- `주문` — 예: "심판청구를 기각합니다."
- `재결요지` — 결정 요지
- `이유` — 결정문 본문
- `청구취지`, `관련법령`, `참조결정`, `따른결정` (확인한 건에서는 비어 있었다)

**결과(인용/기각) 값**: 따로 정해진 항목은 없다. `사건명` 끝의 괄호(예: "…여부(기각)")와 `주문`에서 읽어 내야 한다.

**주의**: 본문 응답에서는 `청구번호`와 `사건번호`가 비어 있었다. 사건번호는 목록에서 받은 `청구번호`를 써야 한다.

## 추가로 확인한 것 (PLAN 3~9번 작업 중)

- **조문 하나만 조회**: 본문 조회에 `JO=005500`(조 번호 4자리 + 가지번호 2자리)을 붙이면 그 조문만 내려온다. 응답에는 장·절 제목(`조문여부`가 "전문")이 함께 오므로 `조문여부`가 "조문"인 것만 쓴다.
- **과거 시점 조문**: `target=eflaw`로 목록을 조회하면 같은 법령의 시행일자별 판이 모두 나온다. 기준일 이전 중 가장 늦은 판을 골라 `MST`, `efYd`(시행일자), `JO`로 조회하면 그 시점의 조문이 내려온다.
- **최근 순 정렬**: 목록 조회에 `sort=ddes`를 붙이면 날짜가 최근인 순서로 온다.
- **본문 검색**: 목록 조회에 `search=2`를 붙이면 사건명이 아니라 본문에서 검색한다.
- **검색어**: 띄어 쓴 단어는 모두 포함된 사건명만 검색된다. 검색어는 1~2개 단어로 짧게 써야 결과가 나온다.
- **자료가 1건일 때**: 목록이 배열이 아니라 객체 하나로 온다.
- **국세법령정보시스템 출처 판결의 본문**: 공개 페이지는 국세법령정보시스템으로 넘어가며, 본문은 그 사이트의 내부 방식으로 불러온다. 법제처 API로는 받을 수 없어 가져오지 않기로 했다.

## 남은 문제

1. **국세법령정보시스템 출처 판결의 본문이 JSON으로 내려오지 않는다.** JSON으로 요청하면 "일치하는 판례가 없습니다"가 오고, HTML로 요청하면 본문 없이 다른 페이지(`https://www.law.go.kr/LSW/precInfoP.do?precSeq=일련번호`)를 가리키는 껍데기만 온다. 조세 판결의 상당수가 이 출처이므로, PLAN 5번(본문 조회 코드)에서 이 페이지에서 본문을 가져올 수 있는지 확인해야 한다.
2. **국세법령정보시스템 출처 판결의 결과(국승/국패) 값이 목록에 없다.** 본문을 가져와야 알 수 있다.
3. **과거 시점 조문(연혁 법령)** 조회는 이번에 확인하지 않았다. 목록에 `현행연혁코드`가 있는 것까지만 확인했다. (PLAN 9번에서 확인)
